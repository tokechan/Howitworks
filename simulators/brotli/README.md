# Brotli Visualizer：ローカル学習用シミュレーター

HTTP受信からBrotli展開までの経路と、入力待ち・形式エラーの分岐を1ステップずつ追う。記事とLTで共通利用することを想定した、ブラウザーで動く独立したページ。

添付されたEvent Loop Visualizerのように、上部に再生操作、左にコード、中央に大きな処理・待機の枠、右にログと出力を配置する。配色はユーザー指定サイトから取得した白・濃紺・青を中心に適用した。[UIと配色の記録](design-notes.md)

## 起動

プロジェクトのルートで実行する。

```sh
node simulators/brotli/serve.mjs
```

ブラウザーで <http://127.0.0.1:4177/> を開く。停止は実行中のターミナルで `Ctrl+C`。Node.jsの組み込み機能だけを使い、パッケージのインストールやビルドは不要。

- `node`：ローカルのJavaScript実行環境で起動する。
- `serve.mjs`：シミュレーターの静的ファイルだけを配信するサーバー。
- `127.0.0.1`：このMac自身。他の端末に向けて待ち受けない。
- `4177`：このサーバーが使うポート番号。

ポートが使用中の場合は、既存のプロセスを止めず、別のポートを指定する。

```sh
node simulators/brotli/serve.mjs --port 4178
```

この場合は <http://127.0.0.1:4178/> を開く。サーバーはGETとHEADだけを受け付け、配信対象も`dist/`の5ファイルに限定する。調査ノート、ホームディレクトリ、他のプロジェクトは配信しない。

## 3つのモード

| モード | 操作と見るところ |
| --- | --- |
| 01 APIの違い | 同じ103バイトのHTTP本文をfetchとnode:httpへ渡す。応答のContent-Encodingを切り替え、デコーダーを通るかと最終サイズを比較する |
| 02 正常な入力待ち | 正常なデータをA・B・Cの断片で届ける。入力待ちで自動再生が一時停止し、「次の断片を届ける」で再開する |
| 03 修正前と修正後 | 不正なブロック切り替えへの判断を左右で比較する。修正後がエラーで終了しても、修正前は不正な状態で入力追加を続け得ることを見る |

最初は01のステップボタン（▷│）で、コードのハイライトと中央の処理を見比べる。02で正常な入力待ちを体験してから、03の判断の違いを見るとつながりを理解しやすい。

共通操作：

- 上部のステップボタン（▷│）と戻るボタン（‹）：1ステップ移動。中央の下にあるステップ名から直接移動することもできる。
- データが移るステップでは、カードが移動元から移動先まで実際に枠をまたぐ。移動元は破線、移動先は実線で強調し、矢印と上部の経路表示を併用する。
- 「今回の移動」の右の↻：ステップを変えず、その移動だけをもう一度見る。Speedを遅くするとカードもゆっくり動く。
- 判定・処理・入力待ちのステップでは、架空のデータ移動を描かず説明を表示する。戻る／複数ステップ先への移動は、その時点の状態を表示する（通信が逆流したという意味にしない）。
- Run／Pause：現在のステップから一定間隔で進む／一時停止する。末尾で停止する。
- Replay：末尾から最初に戻って自動再生する。
- リセット（↻）：再生を止めて最初のステップへ戻る。
- Speedスライダー：1ステップの表示間隔を900〜3600ミリ秒で調整する。実際の通信時間や処理速度を表すものではない。
- モードや応答ヘッダーを変更すると、再生を停止して準備へ戻る。
- キーボード：ボタン等にフォーカスがないとき、左右の矢印キーで移動、Spaceで再生・一時停止。フォーム操作やブラウザーの修飾キーは妨げない。
- 出典とモデルの範囲：画面下のボタンで、実測と模式表現の区別・一次資料を開く。表示中は自動再生を停止する。
- 「動きを減らす」またはOSの同等の設定では、移動・色のトランジションを無効にする。ステップ操作と経路説明は維持する。

カードの経路：

| モード | カードの流れ |
| --- | --- |
| APIの違い | ヘッダー、続いて103Bの本文がHTTP応答から各APIへ。読み出しでfetchの4,280Bを展開後の枠へ、node:httpの103Bを圧縮済みの枠へ。ヘッダーなしでは両方とも圧縮済みの枠へ |
| 正常な入力待ち | 未到着の断片 → 到着の記録 → デコーダー。完了するとデコーダー → 展開された本文。到着の記録は履歴であり、入力を二重に保持するという意味ではない |
| 修正前と修正後 | 共通入力 → 両デコーダー。分岐ではデータではなく判定を伝えるカードが継続／終了へ。修正前だけ追加の入力が戻り、修正後は停止を維持 |

移動の速度、経路、同時表示は説明用。APIの比較は別々のリクエストであり、1本のHTTP応答が物理的に2つへ分裂するわけではない。

## 実測とモデルの区別

正常系の最終値は[HTTP実験](../../experiments/brotli-http/run.mjs)と[検証記録](../../notes/brotli-http-auto-decode-2026-10-27.md)に基づく。2026-10-27、Node.js v24.22.1 / Undici 7.30.1、HTTP/1.1で実測し、ユーザーの追試でも一致した。

- fetch＋Content-Encoding: br：元の本文4,280バイトと完全一致。
- node:http＋Content-Encoding: br：圧縮済みの103バイトと完全一致。
- fetch＋Content-Encodingなし：同じく圧縮済み103バイトと完全一致。

全リクエストにAccept-Encoding: brを明示した。HTTP本文のサイズであり、通信全体のサイズではない。Content-Lengthは送信時の本文サイズを表す。

シミュレーター内では、上記の実測結果と公式資料に整合する状態モデルを実行している。Node.jsのHTTPクライアントや本物のBrotliデコーダーをブラウザーで動かしているわけではない。

次の内容は説明用の模式表現：

- 各ステップ、到着時刻、断片の分割、入力待ちの位置。
- 8バイトの内部バッファにおける枠の埋まり方と、範囲外の領域。
- 日本語の擬似コード、処理の細部を省略した経路。

バッファの塗られた枠の数は実際の残存入力バイト数ではなく、状態を示す演出。修正後の図はエラー以降に追加しないことを表し、実際のメモリ内容・解放のタイミングを示さない。入力待ちのモードも、実際のデコーダーが完了前に出力しないと主張するものではない。本文全体のサイズを完了時に表示する。

脆弱性、メモリ破損、任意コード実行を実行再現しない。Node.js v24.22.1は公式に修正取り込みが記録された版で、正常系の実験結果を脆弱性の再現根拠には使わない。

## 出典

2026-10-27確認。画面下の「出典とモデルの範囲」からも参照できる。

- [Node.js v24.22.1同梱Undiciのfetch](https://github.com/nodejs/node/blob/v24.22.1/deps/undici/src/lib/web/fetch/index.js#L2256)：brに対してデコーダーを選ぶ経路。
- [Node.js公式の脆弱性説明](https://nodejs.org/en/blog/vulnerability/october-2026-security-releases#nodejs-brotli-decoder-out-of-bounds-write-permits-remote-code-execution-cve-2026-111497---high)：不正なブロック切り替え、入力待ちとの混同、8バイトの内部バッファ、メモリ破損の影響。
- [Google Brotliの修正差分](https://github.com/google/brotli/commit/0ed4268a4401abcb4472096340477cf4af7d1a2b)：成功・入力不足・形式エラーの区別と伝播。
- [JPCERT/CC](https://www.jpcert.or.jp/at/2026/at260034.html)、[Brotli v1.2.1](https://github.com/google/brotli/releases/tag/v1.2.1)、[公式リポジトリ](https://github.com/google/brotli)：CVE、上流リリース、公式実装。
- [Node.js v24.22.1](https://nodejs.org/en/blog/release/v24.22.1)：上流修正の取り込み。

## ファイルと検証

```text
simulators/brotli/
  serve.mjs           ローカル配信
  dist/
    index.html        画面と出典
    styles.css        レイアウト・指定パレット・UI部品・動き
    model.mjs         各シナリオの状態モデルとカードの経路
    app.mjs           操作・再生・画面更新
  tests/
    model.test.mjs    説明の成立条件を確認するテスト
```

```sh
node --test simulators/brotli/tests/model.test.mjs
```

10個のテストで、実測結果との一致、入力待ちからの再開、形式エラー後の停止の維持、修正前後の境界の違い、戻る操作で未来の状態が残らないことに加え、カードの経路がその説明と矛盾しないことを確認する。

ローカルHTTP応答、JavaScript構文、3モードのブラウザー操作、入力待ちでの自動停止と再開、ヘッダー変更、速度スライダー、出典表示、レスポンシブ表示も確認する。具体的な確認結果は[実装・検証記録](verification.md)に残す。

`dist/`はビルド不要の静的ファイル一式。将来GitHub Pagesのサブディレクトリへ配置し、記事やSlidevからiframeで読み込めるよう、内部アセットは相対URLで参照している。今回はローカル実装のみで、公開やSlidevへの組み込みは行っていない。
