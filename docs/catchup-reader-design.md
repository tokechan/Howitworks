# 技術情報の収集とMarkdownリーダーの設計案

2026-10-31更新。初期機能を「新着のタイトル・リンク一覧」に決定。収集処理・画面・Cloudflareリソースは未実装。

フロントエンド技術の新着情報を自動で集め、ブログに「気になる最新情報」の一覧を公開する。まずタイトルとリンクを一覧化し、本文は元サイトで読む。深掘りしたテーマは自分の記事へつなげる。Markdownリーダーは、本文取得・表示を追加する段階で扱う。

## 決まっていることと検討すること

| 項目 | 状態 |
| --- | --- |
| 目的 | 情報のキャッチアップを自動化したい |
| 公開する入口 | ブログの「気になる最新情報」一覧 |
| 実装との関係 | 既存のHono＋Viteの静的記事と、自作アイランドの実験に組み合わせる |
| 初期機能 | 新着のタイトル・リンクを一覧にする。ユーザー選択により確定 |
| 本文取得・AI要約 | 初期機能には含めない。必要になった段階で追加する |
| 公開一覧への追加 | 収集後に選ぶか、登録した情報源の新着を自動掲載するかは未決定 |
| 最初の情報源 | 少数の公式ブログ・リリース情報から選ぶ。具体的な購読先は未決定 |

## 情報の流れ

1. **見つける**：登録済みのRSS／Atomを定期的に確認する。
2. **取り出す**：タイトル、リンク、情報源、提供されている公開・更新日、項目IDを取り出す。RSSに本文が含まれていても、初期版では本文を保存・表示しない。
3. **整理する**：同じ情報源の項目IDやURLで二重登録を防ぐ。取得日時・初回発見日時も保存する。
4. **一覧で読む**：新しい情報を一覧に並べ、タイトルから元の記事へ移動できるようにする。情報源と日付を補助表示する。
5. **記事に育てる**：気になったテーマを既存の調査ノート・検証・記事・LTの流れへ渡す。

公開・更新日が提供されない場合は推測で埋めず、必要に応じて初回発見日をその名称で表示する。取得失敗時は既存の一覧を保持し、失敗を「新着なし」と区別して記録する。既読管理、タグの自動分類、全文検索、要約、本文表示は初期版に含めない。

## 最初の構成案

```text
Cron Triggers
  → 収集用Worker
  → RSSなどから新着を発見
  → タイトル・URL・情報源・日付をD1へ保存
  → Hono API
  → ブログ内のReactアイランドで新着一覧を表示
  → 元の記事を開いて読む
```

初期はCron Triggers・Workers・D1を中心にする。Queuesは取得処理を分割し、失敗した項目を再処理したくなった時に追加する。Workflows・R2・AIは初期構成には入れない。

公開用APIは掲載対象の項目を返す。最初の購読先はコード側の設定で管理し、購読先を編集する管理画面は作らない。個人の既読管理や掲載判断の画面を追加する場合は、本人用の操作として別途設計する。

今のブログはHonoがビルド時にHTMLを作る。収集用のHono APIはCloudflare上でリクエストを受けて動く。両者の実行場所とタイミングを区別する。GitHub Pages向けの静的ブログを維持したまま、情報一覧の島だけがCloudflare APIを読む構成も選べる。

Pagefindは生成済みの自分の記事の検索に使う。APIから後で取得した新着一覧は、そのままではPagefindの索引へ入らない。収集情報の検索・絞り込みが必要になった時に、Hono APIとD1で扱う案とする。

## 最小の縦断実験

Cloudflare ChangelogはRSSが公式に案内されているため、最初の取得対象の候補になる。まずローカルで1つのRSSを手動取得し、タイトル・リンクの保存から一覧表示までをつなぐ。再実行しても二重登録されないこと、取得失敗で一覧が消えないこと、日付の欠落を扱えることを確認する。その後、定期実行と購読先の追加へ進む。

Reactは一覧の読み込み中・失敗・再取得の表示に使う。TanStack Queryの導入は、取得状態やキャッシュを比較したい段階で判断する。初期版のためだけに状態管理ライブラリを増やす必要はない。

## Markdownリーダーへの拡張

本文もこのブログ内で読みたくなった段階で、公開されたMarkdown URLや、対応サイトの `Accept: text/markdown` を利用する。応答のContent-Typeを確認し、未対応ならHTMLからの本文抽出や元サイトへのリンクを使う。

その後、必要なら日本語要約・分類、既読・あとで読む、本文検索を追加する。機械生成の要約と自分のコメントは区別する。本文の保存・表示範囲は情報源ごとに決め、取得できることをそのまま全文の再公開条件とは扱わない。
