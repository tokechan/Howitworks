# RSS一覧とブログ基盤の実現可能性検証

2026-10-31。ユーザー依頼：実装せず、認証不要の範囲で設計と検証を進め、依存関係のトレードオフは本人へ返す。公開から3日経過した最新版を基本とする。

## 境界

- 書き込み先はこの検証ディレクトリのみ。アプリ本体、既存記事、完成版LT、既存設定・lockfileは変更しない。
- 既存ファイルの削除は禁止。開始時の既存ファイル52,602件を存在確認し、原本164件のハッシュを比較する。
- 作成するコードは再実行できる検証専用の短いプログラム。ブログ機能として組み込まない。
- 外部アクセスは公開ドキュメント、公式サイト・RSS・公開GitHubリリース、npm公式レジストリ、Node.js公式リリース情報の読み取りだけ。認証・秘密値の読取・ログイン・外部リソース作成・deploy・Git操作は行わない。
- Node.js候補の実行確認では、nodejs.org公式のdarwin-arm64アーカイブとSHASUMS256を新設フォルダ内へ取得する。SHA256と展開パスを点検し、そのフォルダ内の実行ファイルを直接指定する。nvm・PATHのユーザー設定・既存Nodeは変更しない。
- 依存導入はこの検証ディレクトリ内だけ。npmキャッシュ・ログもここへ置き、install scriptsは無効にする。Macユーザー設定の7日は変更しない。
- バージョンの基準は検証開始時刻から72時間前。prereleaseとdeprecatedを候補から除く。直接依存だけでなく、生成したlockfileの間接依存も公開日時を点検する。
- リリース待機が重要な修正を妨げる場合、例外を自動で設定せず判断事項として記録する。

## 検証項目

| ID | 問い | 確認方法 |
| --- | --- | --- |
| versions | 最新候補と3日待機済み候補は何か | npm公式の公開時刻・engines・peerDependenciesを保存 |
| feeds | 実在する情報源から新着を取れるか | 公式ページのフィード案内、RSS/AtomのHTTP応答・解析 |
| dependencies | 最新候補を一緒に解決できるか | 隔離した依存解決、peer検査、lockfile年齢検査 |
| parser | Workersに持ち込めるRSS解析方式か | RSS/Atom/名前空間/欠落/不正入力の小さな検証 |
| runtime | ローカルWorkers/D1で処理できるか | Miniflareの実ランタイムで解析・重複登録・失敗時保持・取得API |
| islands | 静的HTMLにReactの島を載せられるか | 隔離Viteビルド・manifest・base・React動作の検証用ページ |
| compiler | Compiler導入は現在のViteと両立するか | 公式手順・peer条件と小さなビルド。未採用の選択肢も残す |
| preservation | 既存データは維持されたか | 存在確認と原本ハッシュを実行後に比較 |

ハーネスは指定した検証を実行し、各回の標準出力・終了コード・開始終了時刻を保存する。失敗記録は上書きせず、修正後は別の実行記録を残す。ローカル合格をクラウド本番確認・公開完了と読み替えない。

依存候補の選定は実験条件であり採用決定ではない。既存のAstro版・完成版LTを最新版へ更新する作業は含めない。
